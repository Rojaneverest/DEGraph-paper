The revenue-code test normalizes each entry by trimming, stripping non-digit characters via `regexp_replace(..., '[^0-9]', '')`, left-padding to 4 digits with `lpad(..., 4, '0')`, and then membership-testing against the literal CMS rehabilitation revenue-code set `{0118, 0128, 0129, 0138, 0158}`. The TOB-only condition is necessary but not sufficient; the revenue-code-only condition is necessary but not sufficient; only their conjunction classifies the claim as Inpatient Rehabilitation. This is in contrast to the Hospice predicate (TOB '81%' + a different revenue set {0651, 0652, 0655, 0656}) and the Home Health predicate (TOB '32%' OR '33%' alone, no revenue check).


This window function assigns a unique row number to each row within a partition of the result set. The partitioning is done by `claim_id`, meaning that the row numbering starts over for each unique `claim_id`. The rows are ordered by `seq_num` in descending order, with null values placed last.

This additional complexity arises from the need to prioritize the "PCP" code based on the `is_pcp_eligible` and `any_pcp_flag` signals, which is not required for `provider_specialty_description`.
