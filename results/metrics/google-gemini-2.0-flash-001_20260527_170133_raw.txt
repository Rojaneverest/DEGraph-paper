Q: What is the relationship between `claim_category` and `claim_categories`? Can a claim have `claim_category = NULL` but `claim_categories` non-empty, or vice versa? Explain why.
Score: None

REFERENCE:
Both columns are driven by the SAME 8 predicates from `build_claim_criteria()` (stored in the `conds` dict): Behavioral Health, Maternity, Skilled Nursing Facility, Inpatient Rehabilitation, Hospice, Emergency/Observation, Durable Medical Equipment, Home Health. They differ only in how matches are combined: `claim_category` is a `when(...).when(...).otherwise(None)` first-match chain returning the FIRST firing category in declaration order (BH wins over Maternity, etc.); `claim_categories` is an `array(when(conds[k], lit(k)).otherwise(None) for k in conds)` accumulator filtered for non-nulls and sorted, returning ALL matching categories. Consequence: it is IMPOSSIBLE for one to be NULL/empty while the other is non-empty. If any predicate fires, `claim_category` = the first match AND `claim_categories` contains at least that match. If no predicate fires, `claim_category = NULL` AND `claim_categories = []` (empty array — not NULL, because `filter()` on a non-null array returns `[]`).

MODEL (google/gemini-2.0-flash-001):

MODEL (google/gemini-2.0-flash-001):

Specifically, the expression is:

```
concat_ws(
    "_",
    coalesce(col("member_uid"), lit("UNKNOWN")),
    coalesce(
        when(col("product_code_hdr") == "MERIDIAN_PPO",  lit("MRD-PPO-001"))
        .when(col("product_code_hdr") == "MERIDIAN_HMO",  lit("MRD-HMO-001"))

        .otherwise(lit("UNKNOWN")),
        lit("UNKNOWN"),
    ),
)
```

This means:

1.  **`member_uid` Handling:** If `member_uid` is NULL, it's replaced with the string "UNKNOWN" using `coalesce(col("member_uid"), lit("UNKNOWN"))`.
2.  **`product_code_hdr` to Plan ID Mapping:** A `when` chain maps `product_code_hdr` to a specific plan ID:
    *   "MERIDIAN\_PPO" -> "MRD-PPO-001"
    *   "MERIDIAN\_HMO" -> "MRD-HMO-001"
    *   "MERIDIAN\_EPO" -> "MRD-EPO-001"
    *   "MERIDIAN\_DSNP" -> "MRD-DSNP-001"
3.  **Unknown `product_code_hdr`:** If `product_code_hdr` doesn't match any of the above, the `otherwise` clause sets the plan ID to "UNKNOWN".
4.  **Plan ID Coalesce:** The outer `coalesce` isn't strictly necessary because the `otherwise` clause already handles the NULL case, but it ensures that if the entire `when` expression evaluates to NULL for some reason, it defaults to "UNKNOWN".
5.  **Concatenation:** Finally, `concat_ws("_", ...)` concatenates the (potentially "UNKNOWN") `member_uid` and the (potentially "UNKNOWN") plan ID, separated by an underscore.

The two-column LEFT JOIN in the `provider_specialty_df` SQL CTE (joining `ranked_providers` to `bronze.provider_registry` on `rendering_npi = npi AND taxonomy_code = taxonomy_code`) ensures the registry lookup is exact — a provider with multiple taxonomy codes maps to exactly the right specialty row.
