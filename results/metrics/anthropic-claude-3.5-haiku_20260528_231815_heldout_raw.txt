REFERENCE:
The CTE uses `ROW_NUMBER() OVER (PARTITION BY claim_id ORDER BY seq_num DESC NULLS LAST) AS provider_rank` inside `ranked_providers`. Partition key: `claim_id` (one ranking sequence per claim). Sort: `seq_num` DESCENDING with NULLS LAST. DESC means the LATEST/HIGHEST `seq_num` value wins — interpreted as the most-recently-added rendering-provider record on the claim. The `WHERE rp.provider_rank = 1` in the downstream `primary_provider` CTE keeps only that rank-1 row per claim. There is no secondary tiebreaker, so two records with identical seq_num are non-deterministically ordered relative to each other (Spark may pick either).

Differences from the diagnosis-ranking Window (`Window.partitionBy('claim_id_hdr').orderBy(F.col('diag_priority').asc_nulls_last(), F.col('icd10_code').asc_nulls_last())`): (a) Implementation site — diag window is a PySpark `Window` object built via `Window.partitionBy().orderBy()` then passed to `.over(diag_rank_window)`; provider window is inline SQL inside `spark.sql("""...""")` using `OVER (PARTITION BY ... ORDER BY ...)`. (b) Sort direction — diag is ASCENDING (lowest priority number / earliest ICD-10 code wins, i.e. clinically most significant); provider is DESCENDING (highest seq_num wins, i.e. latest-added). (c) Tiebreaker — diag has a two-key sort (priority, then code as tiebreaker); provider has a single ordering key (seq_num). (d) Filter use — diag rank is consumed by a wide-pivot `MAX(CASE WHEN diag_rank = i THEN ...)`; provider rank is consumed by `WHERE provider_rank = 1` to keep just the top row.
