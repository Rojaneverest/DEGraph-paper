[TQ10] window-function-impact / medium
Q: The dedup window in `silver/inventory_daily.py` orders by `snapshot_ts` descending. Explain what the descending order achieves, and what the TWO filters in this file do.
Score: None

REFERENCE:
The dedup window is `Window.partitionBy('warehouse_id', 'product_id', 'snapshot_date').orderBy(F.col('snapshot_ts').desc())`, with `row_number()` -> `rn`. The DESCENDING order on snapshot_ts means the most recent (highest snapshot_ts) snapshot within each (warehouse, product, day) gets rank 1 — so the pipeline keeps the LATEST snapshot when the WMS emits multiple snapshots in a single day (e.g. morning baseline + midday recount). The TWO filters: (1) `filter(F.col('rn') == 1)` — the dedup filter, keeping only that latest snapshot per (warehouse_id, product_id, snapshot_date); (2) `filter(F.col('on_hand_units') > 0)` — the empty-stock filter, dropping rows with zero on-hand units (no analytical signal for turnover). MODEL (google/gemini-2.0-flash-001):
The descending order in the dedup window of `silver/inventory_daily.py` ensures that when multiple snapshots exist for the same warehouse, product, and day, the most recent snapshot (highest `snapshot_ts`) is kept.

The two filters in this file do the following:

1.  `rn == 1`: This filter keeps only the first row within each window partition, effectively deduplicating the snapshots to the latest one per (warehouse, product, day).
2.  `on_hand_units > 0`: This filter removes rows where the on-hand stock is zero. This is done because rows with zero on-hand stock carry no analytical signal for the turnover gold table.
