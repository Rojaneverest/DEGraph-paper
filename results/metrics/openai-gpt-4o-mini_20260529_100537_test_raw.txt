The DESCENDING order on snapshot_ts means the most recent (highest snapshot_ts) snapshot within each (warehouse, product, day) gets rank 1 — so the pipeline keeps the LATEST snapshot when the WMS emits multiple snapshots in a single day (e.g. morning baseline + midday recount). The TWO filters: (1) `filter(F.col('rn') == 1)` — the dedup filter, keeping only that latest snapshot per (warehouse_id, product_id, snapshot_date); (2) `filter(F.col('on_hand_units') > 0)` — the empty-stock filter, dropping rows with zero on-hand units (no analytical signal for turnover). Note snapshot_date itself is derived earlier as `to_date(snapshot_ts)` and is the partition key for the dedup window; `utilization_pct = reserved_units / when(on_hand_units==0, None).otherwise(on_hand_units)` is computed before the on_hand>0 filter.

MODEL (openai/gpt-4o-mini):
In `silver/inventory_daily.py`, the deduplication window orders by `snapshot_ts` in descending order to ensure that when multiple inventory snapshots are available for the same `(warehouse_id, product_id, snapshot_date)`, the most recent snapshot (i.e., the one with the latest timestamp) is retained. This is crucial for maintaining the most up-to-date inventory information, as older snapshots should be discarded in favor of the latest data.

1. **Filter for deduplication (`rn == 1`)**: This filter keeps only the latest snapshot per `(warehouse_id, product_id, snapshot_date)` by retaining rows where the row number (`rn`) assigned by the window function is equal to 1.
