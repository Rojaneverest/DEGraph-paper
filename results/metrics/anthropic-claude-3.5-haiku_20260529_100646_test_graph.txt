Q: Based on the body of `DeltaMergeSink.run()` in `utils/sinks.py`, what does the sink do on the very first run (when the target table does not yet exist) versus on subsequent runs, and what columns/keys drive the merge?
Score: None

REFERENCE:
`DeltaMergeSink.run(df)` branches on whether the target already exists: `if not spark.catalog.tableExists(self.target_table): df.write.format("delta").saveAsTable(self.target_table); return`. So on the FIRST run (table absent) it simply creates the table with a plain Delta `saveAsTable` — no merge. On SUBSEQUENT runs (table exists) it performs a MERGE: `target = DeltaTable.forName(spark, self.target_table)`, builds the match condition by joining the merge keys (`" AND ".join(f"t.{k} = s.{k}" for k in self.merge_keys)`), then `target.alias("t").merge(df.alias("s"), condition).whenMatchedUpdateAll().whenNotMatchedInsertAll().execute()` — i.e. update matched rows in place and insert new ones (SCD-Type-1 upsert). An optional `update_condition` (default None) can gate the `whenMatchedUpdateAll`. For `gold/product_performance.py` the merge keys are `["product_id", "order_date"]`, so matching is on `t.product_id = s.product_id AND t.order_date = s.order_date`.
